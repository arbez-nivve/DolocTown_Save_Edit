# Doloc Town Save Editor

一个面向 Windows 的《多洛可小镇》非官方存档修改器，可读取、编辑并重新加密游戏存档。

目前支持常用角色属性、背包物品、箱内物品、种子基因以及完整 JSON 编辑。程序以“尽量不破坏原始存档”为首要原则：默认另存为新文件，覆盖前自动备份，写入后重新解密并比对数据。

> [!WARNING]
> 本工具并非游戏官方工具。修改存档前请退出游戏，并自行保留原始存档。优先使用“另存为修改版”，确认游戏能够正常读取后再替换正式存档。

## 功能

### 常用属性

- 玩家名称与金钱
- 当前/最大生命
- 当前/最大能量
- 当前/最大精神
- 农场等级
- 存档版本、游戏日期、游玩时长和当前场景概览
- 背包等级只读展示

### 物品栏编辑

- 添加、复制、删除物品，以及修改数量和已有属性
- 展开纸箱、塑料箱等容器，并编辑箱内物品
- 修改箱子耐久、外观索引等存档中已经存在的字段
- 修改种子的孵化进度、克隆标记和基因列表
- 扫描当前存档中的真实物品样本与基因记录
- 按物品 ID、类型或基因筛选可添加的物品
- 通过完整物品 JSON 编辑未提供专用控件的复杂属性

物品编辑遵循原存档的槽位结构：

- 背包可以是 10、20、30、40 格或其他原有数量，程序不会假设固定容量。
- 只能修改格子内的物品，不能增加或减少格子。
- 删除物品只会把对应格子清空，不会移动后续物品。
- 背包已满时不能继续添加物品。
- 高级 JSON、导出和保存阶段都会检查背包格子数及容量相关字段是否被修改。

### 高级 JSON

- 查看并编辑完整存档结构
- 打开已导出的 `.json` 文件
- 格式化与结构验证
- `Ctrl+F` 搜索文字、字段名或 ID
- 匹配数量与当前结果高亮
- 可选区分大小写
- `Enter` / `F3` 跳到下一处，`Shift+Enter` / `Shift+F3` 跳到上一处

搜索采用原文匹配，不会把输入内容当作正则表达式。

## 快速开始

### 使用发布版

1. 在 GitHub 仓库的 **Releases** 页面下载最新的 `DolocSaveEditor.exe`。
2. 退出游戏，并备份需要修改的 `.data` 存档。
3. 启动修改器，点击“打开存档”。
4. 完成修改后优先选择“另存为修改版”。
5. 将修改后的文件放到正确的游戏存档位置，并在游戏中确认能够正常加载。

也可以把存档拖到程序快捷方式，或从命令行把路径作为启动参数传入。

## 物品栏使用说明

1. 打开存档后进入“物品栏”页面。
2. 选择左侧的物品，在右侧修改数量、耐久、基因等属性。
3. 切换物品、切换页面或保存时会自动应用当前属性，也可以主动点击“应用属性”。
4. 展开箱子即可查看和编辑内部物品。
5. 选择空槽后添加物品，会放入该槽；选择箱子后添加物品，会放入箱内的可用空槽。
6. “复制所选”会复制完整属性；复制箱子也会复制箱内内容。

物品样本库只包含当前存档中实际出现过的内容，不代表游戏的完整物品数据库。新增样本的数量默认为 1，物品名称显示存档原始 ID，不猜测中文名称。

案例存档中未发现统一的“可出售”独立字段，因此程序不会凭空写入此属性。如果某个物品本身带有 `isSellable`、`canSell` 或 `sellable` 字段，程序会将其作为已有布尔属性显示。

## 存档安全机制

- 校验 `DOLOC-TOWN:` 文件前缀、Base64 数据和加密内容
- 校验必要的 `farmData`、`baseData` 等结构
- 同步更新存档中重复保存的常用字段
- 默认另存为新文件，不覆盖原存档
- 覆盖现有 `.data` 文件前创建带时间戳的 `.bak` 备份
- 先写入同目录临时文件，再进行原子替换
- 写入后立即重新解密并逐字段比对
- 回读验证失败时尝试恢复备份
- 保护背包格子数、锁定状态、列数和背包等级

## 兼容性与限制

| 项目 | 状态 |
| --- | --- |
| 操作系统 | Windows |
| Python | 3.10 或更高版本 |
| 最初开发格式 | 游戏版本 `1.00.05` 的存档 |
| 当前结构测试 | 游戏版本 `1.00.07` 的案例存档 |
| 加密回读 | 已测试 |
| 游戏内实际加载 | 尚未完成系统性验证 |

存档结构可能随游戏更新变化。即使程序能够成功解密和回读，也不等于游戏一定接受所有修改。数量上限、基因组合效果以及具体游戏规则无法仅从存档结构确认。

日期字段还包含 `TotalDays`、`TotalTUs`、星期等联动值，因此目前只在常用页面展示；如需修改，只能在高级 JSON 中自行处理并承担对应风险。

## 从源码运行

克隆或下载仓库后，在项目目录执行：

```powershell
python -m pip install -r requirements.txt
python app.py
```

也可以把存档路径作为参数传入：

```powershell
python app.py "C:\path\to\doloc-save-0.data"
```

## 构建 Windows EXE

安装依赖后执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

输出文件位于：

```text
dist\DolocSaveEditor.exe
```

## 测试

运行基础测试：

```powershell
python -m unittest discover -s tests -v
```

如果本地有可用于测试的案例存档，可以指定案例目录后运行完整测试：

```powershell
$env:DOLOC_SAMPLE_DIR = "C:\path\to\doloc-samples"
python -m unittest discover -s tests -v
```

真实案例测试只读取输入文件，修改后的测试存档会写入临时目录。界面测试需要可用的 Windows 桌面会话。

> [!CAUTION]
> 不要把真实存档、解密后的 JSON、备份文件或包含个人路径的环境配置提交到公开仓库。存档可能包含玩家名称、游玩记录及其他个人游戏数据。项目的 `.gitignore` 已默认排除常见存档和导出文件，但上传前仍应检查 GitHub 的文件列表。

## 项目结构

```text
app.py                 主窗口、常用字段和保存流程
inventory.py           物品结构校验、查找及增删改操作
inventory_ui.py        物品栏与箱内物品编辑界面
json_search.py         高级 JSON 搜索
save_codec.py          存档解密、加密、备份与回读验证
tests/                 编解码、物品栏、界面及案例回归测试
build.ps1              Windows EXE 构建脚本
requirements.txt       Python 依赖
```
